# 0006. The name `GeneralSymbolicExpression(R, A)`

- Status: Accepted
- Date: 2026-11-26
- Decided by: Bill Page
- Spec: §3.3, §5

## Context

The prototype of design (I) was called `SymbolicPair(R, A)` (abbreviation `SYMPAIR`). "Pair" names an internal choice, the representation by written form and value, rather than what the domain is for: `SymbolicExpression` with an axiom set chosen by the user.

## Options

1. `GeneralSymbolicExpression(R, A)`: follows the FriCAS convention that the "General" version of a domain makes one of its fixed choices a parameter, as `GeneralDistributedMultivariatePolynomial(vl, R, E)` does for the term ordering of `DistributedMultivariatePolynomial(vl, R)`.
2. `SymbolicPresentation(R, A)`: matches the spec's word, but in FriCAS "presentation" means generators and relations (`GroupPresentation`), which describes design (II) better.
3. `SymbolicExpressionWith(R, A)` or similar: no FriCAS precedent.

## Decision

Option 1: `GeneralSymbolicExpression(R, A)`, abbreviation `GSEXPR` (free in FriCAS 1.4.0, checked with `)abbrev query`), files `src/algebra/gsexpr.spad` and `src/input/gsexpr.input`. `SymbolicExpression(R)` is to be `GeneralSymbolicExpression(R, A_P)`.

## Consequences

- The word "pair" remains only where the spec describes the representation (§3.3).
- `SymbolicExpression` is still the name of the 2017 domain in `src/algebra/sexpr.spad`; the new definition takes it over when that file is reworked. Until then, write `GeneralSymbolicExpression(R, [identities, annihilation, involutions, numerals])`.
- Records and notes written before this date keep the old name.
- To revisit with design (II): `Symbolic(R, A)` is easily confused with `GeneralSymbolicExpression(R, A)`.
